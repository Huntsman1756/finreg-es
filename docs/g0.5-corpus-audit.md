### G05-015

La secuencia de comprobacion queda documentada sin reparar el valor:

1. El CSV ESMA contiene exactamente `549300746K71T6YJCV41` en la linea fisica
   171. El parser conserva el mismo valor, sin diferencias de caracteres ni
   cambios de normalizacion.
2. Tiene 20 caracteres ASCII alfanumericos. Los digitos publicados son `41`,
   mientras que el calculo ISO 17442 mod 97-10 para los primeros 18 caracteres
   exige `49`.
3. La consulta exacta al API oficial GLEIF devuelve HTTP 404; la respuesta esta
   conservada con hash en el artefacto de evidencia.
4. La lista oficial CNMV H2, pagina 7, confirma la denominacion (con variante
   de puntuacion), `PSC (ESPAÑA)`, el servicio `Canje criptos por fondos` y la
   fecha `31/07/2026`, pero no publica LEI, NIF ni numero registral.

La causa establecida es `SOURCE_DATA_QUALITY`, no `PARSE_BUG` ni
`NORMALIZATION_BUG`. La resolucion es: conservar `raw_value`, exponer
`identifier_validity=INVALID`, prohibir el join automatico por LEI y mantener
`identity=IDENTITY_GAP` con revision manual. La evidencia CNMV es corroboracion
de listado, no un identificador alternativo suficiente bajo W6; por eso no se
promueve automaticamente a `EXACT` ni se inventa una reparacion.

G05-012 presenta el mismo tipo de defecto de fuente, pero con longitud 19; su
resultado original `LEI_CHECKSUM_INVALID` es correcto como bloqueo, aunque es
demasiado grueso para distinguir formato de checksum. Tambien queda preservado
para una futura mejora diagnostica.

### Disposiciones de las 40 divergencias

- Las 18 `COVERAGE_GAP`, las 10 `SOURCE_CONTRACT_GAP` y las 10
  `SEMANTICS_GAP` se conservan como gaps del contrato y no generan assessment.
- Las dos `IDENTITY_GAP` de LEI se conservan como datos raw invalidos y bloquean
  el join automatico.
- Las ocho omisiones de `expected_contract_risks` quedan registradas como
  decision pendiente (`G05-B-F04`); no se edita el ground truth durante este
  corte.

No se inicia G0.6. El siguiente cambio permitido es un commit sucesor que
repare la anotacion del runner y, solo tras una decision explicita respaldada
por evidencia primaria, resuelva las omisiones de preregistro.
